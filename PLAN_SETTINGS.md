# План: настройки по секциям

## Зачем

Отдельный файл настроек нужен и останется: 90 параметров — это реестр,
прятать его в код проверок нельзя. Дорого обходятся две ДРУГИЕ вещи:

1. Опечатка молчит. setting("SPEED_ENABLE") возвращает None, не падая.
   Таких мест чтения 169. Это уже стоило нам потери SPEED_TIER_TAGS.
2. Плоское пространство имён: SPEED_ENABLED и REACHABILITY_TIMEOUT стоят
   рядом, группировки нет.

## Решение

Вложенные дата-классы. Доступ через атрибут вместо строки:
    settings.speed.enabled        было: setting("SPEED_ENABLED")
    settings.log.console_level
    settings.paths.db

Что это даёт: автодополнение IDE, поиск по использованиям, и опечатка
падает громко (AttributeError), а не уходит тихо в None.

Что НЕ меняется: имена в .env. SPEED_ENABLED остаётся SPEED_ENABLED —
это внешний контракт, его нечём заменять.

## Раскладка

Измерено: 87 полей из 90 раскладываются по префиксу автоматически,
исключения — 3 (FLASK_HOST, FLASK_PORT, GH_DEPLOY_REPO).

## Порядок работ

### Этап 1. Фундамент — за координатором
Не делегируется: ошибка в структуре разошлась бы по 169 местам.

- Вложенные дата-классы в config/settings.py.
- Правило склейки: имя в .env = префикс секции + имя поля. Явные
  исключения перечисляются списком, а не угадываются.
- СЛОЙ СОВМЕСТИМОСТИ: setting("SPEED_ENABLED") продолжает работать и
  возвращает то же значение. Он нужен, чтобы дерево оставалось рабочим
  весь период миграции, и удаляется на этапе 4.
- setting() начинает ПАдать на неизвестном имени (сейчас молчит).
  Ошибку даём с подсказкой похожих имён.

### Этап 2. Перевод мест чтения — за агентами
169 мест в 26 модулях. Наборы файлов не пересекаются.
Агенту достаётся простая механическая замена с сохранением смысла:
значение читается там же, где читалось.

### Этап 3. Проверка — за координатором
- тесты зелёные на каждом шаге;
- сверка: для каждого поля значение из вложенного доступа совпадает
  со значением из .env (это главная проверка, она ловит ошибку склейки
  имён);
- замер: сколько мест осталось со строкой.

### Этап 4. Удаление слоя совместимости — за координатором
setting("ИМЯ") удаляется, остаётся только атрибутный доступ.
Проверка: grep не находит ни одного строкового чтения.

## Главный риск

Ошибка склейки имён: поле называется speed.enable, а .env ждёт
SPEED_ENABLED — значение тихо становится None. Страховка — сверка всех
90 полей с .env на этапе 3, а не на глаз.

## Чего не делаем

- TOML/YAML: заменяет один файл двумя ради группировки, которую даёт
  вложенность классов;
- pydantic: новая зависимость и вторая модель мышления в личном
  скрипте;
- автоконстанты вида X = setting(X): это был старый env.py, его снесли.
