# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),

## [2.5.2]

### Changed
- **Чтение настроек переведено с имён-строк на атрибуты.** 90 настроек
  разложены по 12 тематическим секциям (paths, core, urltest, sub, country,
  reach, speed, web, deploy, log, pipeline, services), каждая — замороженный
  дата-класс. Раньше: setting("SPEED_ENABLED"). Теперь:
  get_settings().speed.enabled
  - Имена в .env НЕ изменились: SPEED_ENABLED остаётся SPEED_ENABLED.
  - Связь «имя поля <-> имя в .env» живёт в одной таблице _LAYOUT в
    config/settings.py. 87 полей выводятся по префиксу, 3 перечислены явно
    (PIPELINE_CUSTOM_CHECKERS_DIR, GH_DEPLOY_REPO, пара FLASK_*).
  - Переведены все 165 мест чтения в 27 модулях. Чтений по строке в проекте
    не осталось ни одного, и это проверяет тест, а не разовая ревизия.
- **Опечатка в имени настройки падает вместо тихого None.** Функция
  setting("ИМЯ") удалена, атрибутный доступ ловит опечатку сам.
  - Почему это важно. Именно так терялись настройки: поле не попадало в
    таблицу соответствия, значение None уезжало в сравнение, и ошибка
    обнаруживалась позже и в другом месте. Так пропал SPEED_TIER_TAGS —
    модуль speed.py не импортировался при живых зелёных тестах.
  - ctx.value("ИМЯ") удалён из PipelineContext и CheckContext по той же
    причине: он искал настройку через getattr(get_settings(), ИМЯ), а после
    разложения по секциям такого атрибута нет — getattr возвращал None
    МОЛЧА, и чекеры падали в int(None).
  - ctx.setting("короткое_имя") остался: это другое, настройки прогона
    (batch_size, check_workers, discovery). Их перекрывают аргументы командной
    строки, и живут они в другом пространстве имён.

### Fixed
- **as_dict() терял 10 настроек.** Словарь ключевался именами полей, а имена
  полей повторяются между секциями: timeout есть в country/reach/urltest,
  enabled — в speed/reach/country/deploy. Ключом теперь служит имя из .env,
  оно уникально; as_dict отдаёт все 90.
- **checkers/base.py и pipeline/context.py читали настройки неверно** после
  разложения по секциям: getattr(get_settings(), ИМЯ) давал None молча, и
  country/reachability падали с «int() argument must be ... not NoneType».
  Теперь идёт проверяемое чтение.

### Verified
- Все 90 значений сверены со старой реализацией на реальном .env:
  расхождений 0 — и по значениям, и по типам.
- 275/275 тестов (было 266/266).
- Импортируются все 61 модуль проекта.
- Работают все точки входа: main.py, pipeline checkers, pipeline status,
  pipeline serve, script.server_store, deploy_config, gensub_api.
- python -m pipeline checkers печатает все четыре чекера.

## [2.5.1]

### Changed
- **Настройки сведены к одному источнику.** Значения больше не лежат
  92 отдельными константами в config/env.py, каждая со своим os.getenv на
  этапе ИМПОРТА. Теперь они живут одним дата-классом Settings
  (config/settings.py): одно поле = одно имя + один тип + одно значение по
  умолчанию.
  - Сбор происходит ОДИН раз и явно: main.py вызывает init_settings() при
    старте и передаёт объект дальше.
  - Приоритет: перекрытия из кода > системное окружение > .env > поле.
  - Перекрытие приводится к типу; мусорное значение не затирает рабочее, а
    уступает ему с предупреждением.
  - Окружение процесса больше не подменяется: .env читается в собственный
    словарь, поэтому подмена настроек в одном тесте не утекает в другой.
  - Проверено сравнением: все 89 настроек дают те же значения, что и раньше,
    расхождений 0.
- **Убрано второе место, где имя настройки дублировалось.** Чекеры читали
  ctx.settings.get("speed_enabled", SPEED_ENABLED) — то есть имя
  настройки называлось дважды: в .env как SPEED_ENABLED и в чекере как
  speed_enabled. Стоило одному из них измениться, и перекрытие молча
  переставало действовать. Появился ctx.value("SPEED_ENABLED") — имя
  называется ровно один раз. Переведены все пять штатных чекеров.
- Чтение настроек переведено на setting("ИМЯ") по всему проекту (26 модулей,
  116 импортов). config/env.py после этого удалён — это был последний
  потребитель.

### Added
- 22 проверки загрузки настроек: разбор .env с кавычками и комментариями,
  приоритет источников, приведение к типу, устойчивость к мусорным
  значениям, наследование полей (PIPELINE_BATCH_SIZE <- URLTEST_BATCH_SIZE,
  LOG_CONSOLE_LEVEL <- LOG_LEVEL) и понятная ошибка вместо AttributeError.

### Removed
- **config/env.py удалён.** Обёртка, добавленная в 2.5.1 ради совместимости,
  отслужила своё: все 26 модулей читают настройки через setting("ИМЯ").

### Fixed
- **Чекер скорости не импортировался.** speed.py брал SPEED_TIER_TAGS из
  config.env, а этого имени в таблице синонимов не было — поле есть в
  Settings, но обёртка его не отдавала. Ошибка обнаружилась только на живом
  запуске: тесты были зелёными, потому что проверяли script/speed_check
  (проверку скорости), а не сам чекер.
- **Тесты не ловили неимпортируемые модули.** test_real_checkers_setup
  собирал чекеры списком url_probe,country,reachability — без speed, то есть
  выпадал ровно тот модуль, который был сломан. Добавлена проверка, что
  импортируются ВСЕ модули проекта, и speed включён в список чекеров.
  Проверено: на сломанной версии новая проверка падает.
- init_settings() пересобирал настройки и отменял ранее заданные перекрытия.
  Повторный вызов без аргументов теперь возвращает тот же объект.
- Разбор .env снимал только одинарные кавычки: значение с двойными
  приходило в настройки вместе с кавычками.

## [2.5.0]

### Fixed
- **Задержка (`ping_ms`) терялась у ВСЕХ серверов.** Регулярка ждала формат
  старых версий sing-box — `available (414ms)`, а 1.14 печатает
  `available: 414ms` через двоеточие. Не находя ничего, парсер молча писал
  `ping_ms = NULL`, поэтому из 1572 серверов задержка была пустая у всех, а
  фильтр `max_ping_ms` отбирал ровно 0 серверов. Теперь принимаются оба формата.
- **`Global` стал достижим.** Он требует ВСЕ 8 целей разом, но `telegram` и
  `github` отвечают заметно медленнее остальных шести: медиана TTFB 2188 мс
  против ~1200 мс у остальных, а порог стоял 2000 мс — не хватало 9%.
  Измерено на 20 серверах: `telegram` проходили 3, `github` — 5, поэтому
  `Global` не получал никто. Пороги подняты до 3000 мс: стало 12 и 15,
  `Global` появился у 9 из 20.
- **Профиль достижимости не измерял, а ждал в очереди.** 8 целей через один
  прокси вставали в очередь ВНУТРИ sing-box, и в результат попадало время
  ожидания, а не отклик сайта. Добавлен семафор на цель
  (`REACHABILITY_PER_PROXY_CONCURRENCY=1`), замер переведён на TTFB.
  Трафик на сервер 1153 КБ → 216 КБ, медиана TTFB 7164 → 1976 мс,
  серверы с тегами 0/46 → 40/47.
- **Утечка процессов sing-box.** На Windows `terminate()` не убивает дерево
  процессов: копился осиротевший `sing-box.exe` (найдено 10 штук, самый
  старый жил 3.5 суток, ~625 МБ). Замена на `taskkill /F /T`.
- **Дедлайн батча не учитывал реальную длительность прогона.** sing-box 1.14
  жёстко ограничен 10 одновременными пробами с шагом 5 с
  (`T = 5с × ceil(N/10)`), из-за чего формула была константой и батч из 100
  не мог уложиться в окно 30 с. Формула переписана через
  `PROBE_SLOTS`/`PROBE_STEP`/`HEADROOM`.
- Флаг страны в имени строки брался из колонки БД, а не из самой строки,
  поэтому фильтр по странам не находил серверы с флагом.
- Gemini: отделено «сервер не грузит страницу» от «сервер медленный».
- `NameError: name 'suppressed' is not defined` — падение скрипта.

### Added
- **Многопоточная проверка скорости по нескольким сайтам сразу.**
  Новый модуль `script/speed_sources.py`: Cloudflare, OVH, Google,
  Microsoft и GitHub опрашиваются **одновременно**, каждый в своём потоке,
  плюс отдельный поток на отдачу. Итог — среднее по ответившим источникам,
  битый сайт в среднее не попадает. Замер: **3.4 с параллельно против
  12.4 с последовательно**. Источники подобраны замером: Yandex и Mail.ru
  отпали (отдают HTML на десятки килобайт), Hetzner рвёт соединение.
- **Измерение скорости сохраняется в базу** (`speed_mbps`, `speed_down`,
  `speed_up`). Раньше оставался только тег `speed-slow`, по которому
  0.4 и 0.9 МБ/с неразличимы. Миграция старой базы автоматическая.
- **Метки «лучших» серверов** (`script/best_tags.py`, параметр `BEST_TOP`).
  Лучший сервер каждого профиля получает дополнительный тег
  `[gemini-best]`; остальные попадают в список как обычно — тег это добавка,

- **Независимые долгоживущие службы** (`pipeline/services/`,
  `pipeline/serve.py`) с очередями: проверка, сбор, публикация и запись

- **Три состояния результата проверки** вместо двух: пинг ответил, таймаут,

- Таймаут на батч sing-box с принудительным убийством и возвратом в очередь.
- Env-переменные: `SPEED_SOURCES`, `SPEED_PROBE_BYTES`, `SPEED_UPLOAD_BYTES`,

## [2.4.0]

### Added
- **Новый режим «щита» от удаления для пинговавшихся конфигов.** В базу
  добавлена колонка `ever_pinged` (1 — сервер пинговался хотя бы раз;
  миграция старой базы автоматическая, маркер `servers.shield-migrated.json`).
  Такие серверы защищены от удаления на `SHIELD_CYCLES=96` проверок.
- Новые env-переменные: `NEW_SERVER_STABLE` (по умолчанию `5`) — stable нового
  сервера до первого удачного пинга, и `SHIELD_CYCLES` (по умолчанию `96`).

### Changed
- **Логика `stable` переписана под «щит»** (`compute_next_state`):
  - каждый **успешный** пинг ставит `stable` не ниже `SHIELD_CYCLES=96` и
    помечает `ever_pinged=1`;
  - каждая **неудачная** проверка вычитает `1`;
  - новый сервер до первого успеха имеет `stable=NEW_SERVER_STABLE=5`.
- **Нижний порог `stable` снижен до `0`** (`PURGE_STABLE_BELOW=0`): в цикл
  проверки импортируются **все** серверы со `stable >= 0` (`check_pool`), а
  дойдя до `-1` сервер считается умершим и больше не импортируется из базы.
- `stats()` и итоговый лог цикла: зоны `alive`/`dead`/`shielded`/`online`/
  `reserve`/`unchecked` вместо `full_ban`/`online`/`reserve`/`unchecked`.
- Whitelist без изменений: `available=1` (результат последней проверки).
- `reset-excluded` возвращает серверы в ротацию со щитом (`ever_pinged=1` →
  `SHIELD_CYCLES`, иначе → `NEW_SERVER_STABLE`).

### Removed
- `FULL_BAN_STABLE`: «мёртвое» значение теперь `PURGE_STABLE_BELOW - 1` (`-1`).

## [2.3.0]

### Changed
- **Переписан принцип удаления серверов из списков/конфигов**:
  - **stable не ограничен сверху** (был потолок `STABLE_MAX=5`): успех проверки
    `+1`, неудача `-1` с полом `FULL_BAN_STABLE=-2`. Давний рабочий сервер
    накапливает «запас прочности»: провал не выбрасывает его ни из проверки,
    ни из списков — `stable=20` после провала становится `19`, и сервер
    остаётся в ротации («в запасе»).
  - **В проверку попадают ВСЕ серверы со stable выше порогового `-1`**
    (`excluded=0`), без ограничений: пул проверки собирается из базы целиком
    (`check_pool`, merge.txt).
  - **Whitelist = результат последней проверки.** Принцип «2 раза не пинганулся —
    убрать из whitelist» удалён вместе с временным чсом. Теперь: сервер
    пинганулся (`available=1`) → добавляется в `whitelist.txt`,
    `/api/whitelist` и деплой; не пинганулся → не добавляется, но остаётся
    в пуле проверки. Реально мёртвый сервер умирает сам: каждая неудача
    списывает `-1`, и за ~(stable + 2) провальных проверок его stable
    опускается до `-2` — срабатывает purge (исключение из проверки).

### Removed
- Временный чс целиком: env-переменные `TEMP_BAN_FAILS` и `TEMP_BAN_HOURS`;
  состояние `fail_streak`/`temp_ban_until` (в старых базах колонки остаются,
  но больше не читаются и не пишутся); CLI-команда `reset-temp-bans`;
  зоны `probation`/`testing`/`proven`/`temp_banned` в `stats()` — теперь
  зоны `full_ban`/`online`/`reserve`/`unchecked`.
- Потолок `STABLE_MAX` и экспортный порог `WHITELIST_EXPORT_MIN_STABLE`:
  критерий whitelist теперь `available=1` (последняя проверка), а не
  `stable > порога`. В `/api/servers` добавлен параметр `?available=1`.

## [2.2.0]

### Added
- **Временный чс серверов** — защита рабочих конфигов от ложного бана в час-пики
  (метод работает вместе со stable и скрыто):
  - в базу добавлены колонки `fail_streak` (серия неудач подряд) и `temp_ban_until`
    (момент окончания бана); миграция старой базы — автоматически при первом открытии;
  - `TEMP_BAN_FAILS` (по умолчанию `2`) неудач подряд → сервер на `TEMP_BAN_HOURS`
    (по умолчанию `12`) часов исключается из проверки и из whitelist;
  - первая проверка после бана решающая: успех → восстановление, неудача →
    полноценный чс (`stable=FULL_BAN_STABLE=-2`);
  - серверы во временном чсе не попадают в `whitelist.txt`, `/api/whitelist`,
    `/api/servers` и merge-пул, даже если их stable выше порога экспорта;
  - CLI: `python -m script.server_store reset-temp-bans`.
- `PURGE_STABLE_BELOW` теперь по умолчанию `-1`: `stable=-1` остаётся в списках
  проверки, в полноценный чс уходит только `stable=-2`. Ошибочно исключённые
  ранее серверы (stable >= порога чс) один раз возвращаются в ротацию при первом
  открытии базы (маркер `servers.tempban-migrated.json`).
- Стейт-машина переходов состояния вынесена в чистую функцию
  `script.server_store.compute_next_state()` — её используют и БД (`record_results`),
  и цикл проверки (`urltest._evaluate_nodes`); в логах батчей и итоговом логе
  появились счётчики `temp-ban`/`temp_banned`, в `stats()` — зоны
  `full_ban`/`probation`/`testing`/`proven`/`temp_banned`.

### Changed
- **Конфигурация переведена на окружение**: `config/settings.py` удалён, вместо него
  тонкий `config/env.py` — все значения читаются из переменных окружения
  (`.env` в корне репозитория; приоритет: системное окружение > `.env` > дефолт).
  Добавлен полноценный шаблон `.env.example` со всеми переменными и комментариями.
  Новые env-переменные: `URLTEST_URL`, `URLTEST_TIMEOUT` (бывш. TIMEOUT),
  `URLTEST_BATCH_SIZE` (бывш. BATCH_SIZE), `TEMP_BAN_FAILS`, `TEMP_BAN_HOURS`,
  `FULL_BAN_STABLE`, `SING_BOX_PATH`, `SING_BOX_OUTPUT_DIR`, `CONFIG_TEMPLATE_DIR`;
  переименованные читаются с новыми именами во всех модулях
  (`main.py`, `urltest.py`, `downloader.py`, `core.py`, `country_check.py`,
  `reachability_check.py`, `server_store.py`, `gensub_api.py`, `deploy_config.py`).

  `DEPLOY_TEMPLATES` (имена через запятую/пробел).
  - Итоговый файл в репозитории называется именем шаблона: из `--path` берётся
    только каталог (`--path configs/latest/config.json` + шаблон `sbc-1.14.json`
    -> `configs/latest/sbc-1.14.json`).
  - Whitelist-URI загружается один раз на всю пачку, ветка репозитория
    определяется один раз; сбой одного шаблона не прерывает остальные
    (`--stop-on-error` — прерывает).
- Авто-деплой в `urltest.py` поддерживает мульти-режим: при заданном
  `DEPLOY_TEMPLATES` (`all` или список имён через запятую/пробел) после цикла
  проверки деплоится каждый шаблон (файл = имя шаблона); без переменной —
  один `DEPLOY_TEMPLATE`, как раньше.
- Плейсхолдер текущего IP в шаблонах деплоя: в JSON вместо адреса пишется
  `{{SERVER_IP}}` (имя настраивается `DEPLOY_IP_PLACEHOLDER`), на этапе деплоя
  он замещается актуальным IP из `DEPLOY_IP_SOURCE` (`--ip-source`) — путь к
  локальному файлу (первая непустая строка) или http(s)-ссылка. Значение
  задаётся в `.env` (`DEPLOY_IP_SOURCE=/home/ray/ubuntu_server_ip/current_ip.txt`).

## [2.0.0] - 2026-08-25

### Breaking changes
- Состояние серверов перенесено из текстовых файлов whitelist.txt/blacklist.txt
  в центральную базу SQLite: singbox-subscribe/source/servers.db.
  При первом запуске база автоматически наполняется из старых файлов
  (значения stable сохраняются) — ручная миграция не требуется.

### Added
- script/server_store.py — центральное хранилище серверов (SQLite, WAL):
  фильтры по stable (export_lines/check_pool), purge_dead, reset_excluded,
  статистика; CLI: python -m script.server_store stats|export|purge|reset-excluded.
- HTTP API: GET /api/servers?min_stable=&max_stable=&limit= и /api/servers/stats;
  /api/whitelist теперь читает базу (stable > порога).
- Потолок стабильности STABLE_MAX (по умолчанию 5): умерший давний сервер
  выпадает из списков за конечное число провальных циклов.
- Тесты хранилища и чистых функций цикла: singbox-subscribe/tests/.

### Changed
- stable ограничен диапазоном [PURGE_STABLE_BELOW, STABLE_MAX]; зоны:
  stable < 0 — исключён из проверки, 0..1 — в ротации, > 1 — в экспорте списков.
- Страна сервера считается известной, если эмодзи есть в имени ИЛИ уже лежит
  в базе, — такие серверы не отправляются на дорогую проверку страны.
- Подписки скачиваются параллельно (SUB_DOWNLOAD_CONCURRENCY, по умолчанию 6).

### Performance
- Проверка страны переписана по мотивам Throne (throneproj/Throne):
  один процесс sing-box на батч прокси (inbound->outbound правила маршрутизации,
  каждый локальный порт привязан к своему конфигу) вместо процесса на каждый
  прокси; гео определяется одним лёгким запросом
  (Cloudflare trace -> api.ip.sb -> ipinfo.io) вместо списка speedtest.net,
  который блокировал датацентровые IP (~40% отказов).
  На живых данных: 6/6 успешных определений за ~10с против ~60% ранее.

### Removed
- Логика blacklist/prune_whitelist_by_blacklist (заменена флагом excluded в базе).
- GeoLite2-Country.mmdb больше не хранится в репозитории.
